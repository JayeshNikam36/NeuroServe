# NeuroServe v0.1.5-kv — a KV cache that shares, reuses and evicts, verified at every step

The end of Phase 3. NeuroServe now owns its KV memory: requests that share a prompt prefix share
its KV blocks, a prompt whose prefix is cached is prefilled from the first new token, released
blocks stay reusable until memory is needed, and every engine step checks that the books balance.

## Highlights

- **Prefix caching.** Full 16-token blocks are identified by a chained XXH64 hash rooted in the
  model, its weights, dtype, block size and RoPE. Every hit is verified token by token before it
  is used. The prompt is then prefilled from the cached offset, and the block holding the last
  prompt token is copied (copy-on-write), so a request never writes into a shared block.
- **Reference-counted blocks, `CACHED` blocks and LRU eviction.** A finished request's blocks stay
  reusable; under pressure the least recently released go first, leaves before their parents.
- **Preemption that keeps the work done.** A preempted request resumes by prefilling its prompt
  plus the tokens it already generated (in chunks when long), reusing its own cached blocks:
  nothing is generated twice, and what it streamed stays valid.
- **Memory-aware admission** from the model's `config.json`: `on-demand` or `worst-case`.
- **Checked, not assumed.** The manager's and the engine loop's invariants after every step, a
  CPU reference implementation as the oracle for 10,000 seeded property-test programs, fault
  injection for every invariant, and Compute Sanitizer.
- **Visible.** `GET /v1/runtime/state` reports occupancy, cached and shared blocks, hits, misses,
  reused tokens, evictions and preemptions.

## Results (RTX 4050 Laptop GPU, Llama 3.2 1B FP16)

Prefix caching on vs off, paired rounds, a fresh server per run, medians over 4 measured rounds:

| Profile, mode | TTFT P50 off → on | output tok/s off → on | hit rate |
| --- | --- | --- | --- |
| `shared_prefix`, 4 requests/s | 1846 → 123 ms (−93%) | 224 → 259 | 82.9% |
| `shared_prefix`, burst | 15.8 → 10.8 s (−31%) | 233 → **339 (+45%)** | 82.9% |
| `memory_pressure` (25% of the pool), 1.5 requests/s | 325 → 149 ms (−63%) | 277 → 280 | 66–74% |
| `memory_pressure` (25% of the pool), burst | 33.2 → 27.9 s (−15%) | 323 → **375 (+17%)** | 69–74% |

- On `shared_prefix` the hit rate equals what a cache that never evicted could reach; under
  memory pressure LRU keeps about 87% of it.
- **30-minute stress run** (24 clients, mixed prefix-sharing load, 5% cancelled mid-stream, a
  quarter of the pool): 3,725 requests and 95,752 evictions with no failure and no invariant
  violation; no block held after the drain; GPU memory flat to the MiB; TTFT, ITL and throughput
  within 2% from start to end.
- **Block size 16** kept on measurements: 2.6% waste, and neither 8 nor 32 changes attention time.
- **Compute Sanitizer** memcheck and racecheck: 0 errors.

## Known limitations

- Prefix caching is off by default in `configs/dev.yaml` (`engine.prefix_caching: true`).
- Only full blocks are shared; a prompt's partial last block is recomputed.
- New prompts are still prefilled in one step under the token budget (chunked prefill of new
  prompts is Phase 4).
- Deterministic, not batch-invariant: at a near-tie the batch or a prefix hit can change a greedy
  choice ([ADR-0006](https://github.com/JayeshNikam36/NeuroServe/blob/v0.1.5-kv/docs/adr/0006-determinism-not-batch-invariance.md)).
